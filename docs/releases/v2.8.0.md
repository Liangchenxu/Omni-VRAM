## 一、做了什么（What Changed）

### 1. 执行子系统并入主干
原先独立的 WDDM-Bypass 仓库被整体合入，形成"源码在 `WDDM-Bypass/`、
可 import 的包在根 `wddm_bypass/`"的双目录布局：
- `WDDM-Bypass/csrc/graph_engine.cu`、`bypass_core.cpp`、`torch_interop.cpp`、
  `include/graph_manager.h`：多图 CUDA Graph 引擎（`WDDMBypassEngine`）。
- `WDDM-Bypass/setup.py`：自带 CUDA 回退（没有工具链时只装纯 Python 层，
  并抛 `BackendUnavailable` 给出精确构建命令）。
- `wddm_bypass/__init__.py`：`Engine` 门面（`capture` / `replay` / 缓冲区 / `stats`）。
- `wddm_bypass/bucketing.py`：`ShapeKey` + `BucketPolicy` + `ShapeRouter`。
- `wddm_bypass/backend.py`：导入隔离、DLL 目录上下文、精确的构建提示。

### 2. 解码层挂载点（`wddm_bypass/integration.py`）
- `DecodePlan`：固定几何 + 命名缓冲 + 输入/输出声明。
- `DecodeHook`：预热 → 捕获 → 回放 → eager 降级，四条路径全部计数。
- `accelerate_decode` / `HookedDecoder`：装饰器与 HuggingFace 形状的 `forward` 挂载点。
- `torch_stream()`：把引擎捕获流包成 `torch.cuda.ExternalStream`。

### 3. 显存池 ⇄ 图引擎接缝
`vram_core/wddm_bridge.py` 的 `WddmExecutionBridge`：把 Paged KV-Cache 显存池
注册成捕获安全的静态缓冲、显存预算闸门、提交/回放统计。

### 4. 文档与发布
- `docs/architecture_masterclass.md`（608 行白皮书）。
- `tests/test_transformer_integration.py`（41 例，含 51 kernel/step 的模拟 Llama decode）。
- README / CHANGELOG / 版本号统一到 `2.8.0`；原生 ABI 版本独立为 `1.0.0`。

## 二、遇到了什么问题与踩坑剖析（Problems & Root Causes）

### 坑 1：Windows 上 nvcc 12.1 拒绝 MSVC 14.4x
CUDA 12.1 的主机编译器白名单早于 MSVC 19.40+，`nvcc` 直接报
`unsupported Microsoft Visual Studio version`。

### 坑 2：`vcvars64.bat` 找得到 `cl.exe`，却缺 `ucrt`
Windows SDK 装在非默认盘时，`KitsRoot10` 注册表项过期，`vcvars` 报出可用的 CL，
但 `INCLUDE` 里没有 `ucrt`，于是每个 `<corecrt.h>` 都失败。

### 坑 3：`ubuntu-latest` 悄悄换成 Ubuntu 26.04，Python 3.9 CI 全红
`actions/python-versions` 里 3.9 只有 22.04 / 24.04 的 Linux 资产，
26.04 上 `setup-python` 直接报 "version '3.9' ... was not found for Ubuntu 26.04"。
（修复提交 `1e6f3ee`：matrix 钉 `ubuntu-24.04`，并把 checkout/setup-python 升到 node24 版本。）

### 坑 4：README 合并冲突与换行符
合入远端 OpenSSF / HuggingFace 徽章时 `README.md` 冲突（`UU`），
两侧同时改动了徽章区与版本亮点段，且一侧是 CRLF、一侧是 LF。

### 坑 5：纯 Python 轮子 vs CUDA 扩展
`pip wheel` 在 Windows 上会尝试编译 CUDA 扩展；即使成功，
产出的 wheel 也不再是 `py3-none-any`，与历史发布形态不一致。

---

## 三、如何解决的（How It Was Solved）

1. **编译器白名单**：给 nvcc 加 `-allow-unsupported-compiler`，并给 STL 加
   `_ALLOW_COMPILER_AND_STL_VERSION_MISMATCH`（MSVC 14.4x 的 `<yvals_core.h>`
   在编译器身份与 STL 不匹配时硬报错，这个宏是 STL 自己文档化的开关）。
2. **SDK 路径**：`setup.py` 自己解析 SDK 根（环境变量 → 注册表 → 磁盘扫描），
   把 `ucrt` / `um` / `shared` 拼进 `INCLUDE`、`um\x64` / `ucrt\x64` 拼进 `LIB`。
3. **CI**：Linux matrix 钉死 `ubuntu-24.04`（3.9 / 3.10 / 3.11 全有资产），
   并清掉 Node 20 弃用告警；随后验证 7/7 job 全绿。
4. **冲突**：保留本地 v2.8.0 正文 + 远端徽章改动，统一转 LF 并补行尾换行。
5. **发布形态**：用 `CUDA_VISIBLE_DEVICES=-1` 构建纯 Python wheel（`py3-none-any`），
   与 sdist 一起 `twine check` 通过后再上传。
