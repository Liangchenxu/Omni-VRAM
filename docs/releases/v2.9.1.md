## 一、做了什么（What Changed）

### 1. `.clinerules`：两条最高优先级铁律
- **【版本号递增铁律（Patch-Only）】**：大/次版本长期锁 `2.9.x`，
  只允许 `2.9.0 → 2.9.1 → 2.9.2`；禁止擅升 `2.10.0` / `3.0.0`；
  `wddm_bypass` 原生 ABI（`1.0.0`）与项目版本解耦，不随 Patch 递增。
- **【版本档案留存铁律（Per-Version Archive）】**：每版必须新建
  `docs/releases/v<版本>.md`，**严禁覆盖旧档案**，档案必须写四块内容：
  做了什么 / 踩坑与根因 / 如何解决 / 验收与实测数据；`docs/releases/` 不得进 `.gitignore`。

### 2. `vram_core/tts_engine.py`：`pyttsx3` 模块级符号 + 运行时守卫
```python
pyttsx3 = None                      # 先绑定，保证 mock.patch 能解析到
_PYTTSX3_AVAILABLE = False
try:
    import pyttsx3                  # type: ignore[import-not-found,no-redef]
    _PYTTSX3_AVAILABLE = True
    ...
except ImportError:
    pass                            # 名字已存在且为 None
```
`_init_backend()` 里补运行时守卫，由既有 `except (RuntimeError, OSError)` 兜住，
退化为 `backend="none"`（不新增崩溃路径）。

### 3. `vram_core/whisper/preprocessor.py`：pydub 零依赖回退
- 模块级 `try: from pydub import AudioSegment / except ImportError: AudioSegment = None`。
- 新增 `_load_wave_fallback(source, target_sr=16000, mono=True)`：
  标准库 `wave` 解码 8/16/32-bit 整数 PCM → 多声道混音 → 线性插值重采样 →
  峰值归一化 `×0.95`（与 pydub 路径同尺度）。
- `load_audio_pydub()` 在 `AudioSegment is None` 时走回退；模块级符号仍可被 mock 拦截。

### 4. `vram_core/realtime_server.py`：终态事件的投递屏障
- `_pump()`：每次成功 `send` 后 `task_done()`；sink 抛异常时先 `task_done()` 再退出
  （否则排队中的 `join()` 永远等不到）。
- `_flush_out_queue()`（barge-in 丢弃）：丢弃的每条也 `task_done()`。
- 新增 `_drain(timeout=_TERMINAL_DRAIN_TIMEOUT=5.0)`：`await queue.join()`，
  超时只记 warning 返回 False，**绝不让死 sink 挂死响应任务**。
- 新增 `_emit_delivered(event_type, **fields)`：先排空 → 入队并投递本事件 →
  **之后**才写 `_event_log`。
- `_run_response()` 的三条 `response.done`（完成 / 空转写 / 失败）改用 `_emit_delivered`。

### 5. 版本与文档
- 版本号 `2.9.0 → 2.9.1`：`vram_core/__init__.py`、`pyproject.toml`、根 `setup.py`、
  README 徽章 + 中英文亮点段；CHANGELOG 新增 `[2.9.1]` 小节。
- 新增 `docs/releases/v2.8.0.md`、`v2.9.0.md`、`v2.9.1.md`（本文件）。

## 二、遇到了什么问题与踩坑剖析（Problems & Root Causes）

### 坑 1（6 个用例）：`mock.patch` 解析不到 `pyttsx3`
报错发生在**测试体执行之前**：
```
AttributeError: <module 'vram_core.tts_engine'> does not have the attribute 'pyttsx3'
```
根因：模块写成
```python
_PYTTSX3_AVAILABLE = False
try:
    import pyttsx3
    _PYTTSX3_AVAILABLE = True
except ImportError:
    pass            # <-- 什么都没绑
```
`import pyttsx3` 抛 `ImportError` 时**不会**在模块命名空间里创建这个名字，
于是 `vram_core.tts_engine.pyttsx3` 根本不存在；`mock.patch` 的目标解析阶段
（`mock.py:get_original()`）直接抛 `AttributeError`。
`softmax` 环境恰好没装 pyttsx3（`find_spec('pyttsx3') = None`），
所以这条路径 100% 触发。

### 坑 2（1 个用例）：pydub 缺失让纯 WAV 也转写不了
`load_audio_pydub()` 在**函数体内** `from pydub import AudioSegment`，
`softmax` 没装 pydub（`find_spec('pydub') = None`）→ `ModuleNotFoundError` 一路冒到
`bridge._prepare_audio()`。讽刺的是：测试用的是**标准库生成的纯 PCM WAV**，
根本不需要 pydub 的能力，只是代码把可选依赖写成了硬依赖。

### 坑 3（1 个用例）：`pending_events()` 剩余 2 条 —— 记录先于投递
```python
def _emit(self, event_type, **fields):
    with self._lock:
        self._event_log.append(event)   # 先记录（events / finished() 读这里）
    self._enqueue(event)                # 再入队（投递由 _pump 任务异步完成）
```
`_run_response()` 连续 `_emit`（最后一轮 `response.audio.delta` 与 `response.done`）
之间没有 await，`_pump` 拿不到执行权；测试的
`wait_for(finished)` 第一次 predicate 调用是**同步**的，一旦日志里已有
`response.done` 就立刻返回 True —— 此刻队列里正好还剩这两条未投递。
所以断言 `pending_events() == 0` 必挂。注意同文件另外 3 处断言写的是
`await wait_for(lambda: session.pending_events() == 0)`，等于用轮询绕过了这个竞态，
反而掩盖了"日志语义 ≠ 投递语义"这个真问题。

### 坑 4：`pip install -e .` 被 torch 的 ABI 检查拦下
```
UserWarning: It seems that the VC environment is activated but DISTUTILS_USE_SDK is not set.
```
用 `vcvars64.bat` 自己激活了 MSVC，但没告诉 distutils "SDK 已就绪"，
torch 担心重复激活会污染 `PATH`，直接拒绝构建。

### 坑 5：`queue.join()` 与"丢弃事件"天然冲突
`asyncio.Queue.join()` 依赖未完成任务计数；若 barge-in 时直接 `get_nowait()` 丢弃，
计数永远不归零，任何 `join()` 都会永久阻塞 —— 这是引入投递屏障时最危险的一处。

## 三、如何解决的（How It Was Solved）

1. **先绑定再覆盖**：模块级 `pyttsx3 = None` 让名字一定存在；
   `import pyttsx3` 成功则覆盖为真模块。这样 `mock.patch("vram_core.tts_engine.pyttsx3")`
   在 `get_original()` 阶段能找到属性，patch 生效后 `pyttsx3.init()` 直接命中 mock。
   初始化处加 `if pyttsx3 is None: raise RuntimeError("pyttsx3 is not installed; ...")`，
   由原有的 `except (RuntimeError, OSError)` 捕获，退化为 `backend="none"` 并打 warning。
   **没有**把 `RuntimeError` 一路抛出，否则 `backend="auto"` 的优雅降级会被破坏。
2. **可选依赖 + 标准库回退**：`_load_wave_fallback()` 用 `wave` 读头与帧，
   `np.frombuffer` 按位宽转换（`uint8-128`、`int16/32768`、`int32/2**31`），
   多声道 `reshape(-1, channels).mean(axis=1)`，重采样用 `np.interp` 在
   归一化时间轴上线性插值（`endpoint=False` 保证长度严格等于
   `round(duration * target_sr)`），最后与 pydub 路径一致的 `peak → ×0.95`。
   因为走的是模块级 `AudioSegment`，测试 mock 该属性时仍然优先走 pydub 分支。
3. **投递屏障**：终态事件改成
   `await _drain()` → `put_nowait(event)` → `await _drain()` → 写 `_event_log`。
   这一步把"日志可见"严格排到"客户端已收到"之后，于是
   **`events` 里出现 `response.done` ⇒ `pending_events() == 0`** 成为不变量。
   同一任务内顺序执行，日志顺序 = 投递顺序，没有打乱任何事件次序。
4. **`task_done()` 补齐**：`_pump` 成功投递后调用；`_flush_out_queue` 对被丢弃的
   每条也调用；sink 异常退出前也调用。三者合起来保证 `join()` 不会永久挂起。
5. **超时兜底**：`_drain()` 用 `asyncio.wait_for(..., timeout=5.0)`，
   死 sink 只记 warning，不会让 `_run_response` 卡死（这一点对真实 WebSocket 断连很重要）。
6. **editable 安装**：`vcvars64.bat` 后补 `set DISTUTILS_USE_SDK=1` 与 `set MSSdk=1`，
   再执行 `pip install -e . --no-build-isolation --no-deps`。
